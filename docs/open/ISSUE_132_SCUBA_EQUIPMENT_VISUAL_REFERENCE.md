# Issue #132 — Scuba equipment visual reference set

**Status:** design / asset planning  
**Issue:** #132  
**Topic:** Recreational scuba equipment abbreviations

## Decision

Add a six-asset visual reference to the existing scuba-abbreviations topic. The images support understanding only; the scored claim stays abbreviation → expansion + broad function.

## Owned assets

1. **SCUBA** — complete self-contained underwater breathing setup in context
2. **BCD** — buoyancy control device
3. **SPG** — submersible pressure gauge
4. **LPI** — low-pressure inflator / BCD inflator assembly
5. **DSMB** — delayed surface marker buoy
6. **DPV** — diver propulsion vehicle

## Visual direction

Use realistic, manufacturer-neutral equipment imagery with one immediately readable subject per asset. Images should be clean enough to understand at phone size without turning into product photography or equipment-selection advice.

Where context is required, keep enough surrounding kit to explain the component relationship while still making the target visually dominant.

## Accuracy gate

Mechanical/component accuracy is mandatory.

Reject any asset with:

- impossible hose routing or fittings;
- malformed gauges or controls;
- invented equipment geometry;
- a target component that cannot be distinguished from adjacent kit;
- a misleading representation of what the abbreviation refers to.

Each accepted image should be compared with authoritative training and manufacturer references for physical plausibility.

## Presentation

Preferred first treatment: six individual visual-reference cards or carousel panels with HTML beneath/around each image for:

- abbreviation;
- full term;
- one-sentence core function.

Do not bake that text into the image.

## Safety boundary

The visual guide does not teach configuration, inspection, maintenance, gas planning, buoyancy skills, emergency response or equipment suitability. It does not create visual-identification evidence for Test.

## Completion for this issue

The issue is ready for implementation once:

- all six individual assets pass mechanical/component QA;
- the target component remains clear at phone size;
- asset provenance/QA notes are recorded;
- existing topic limitations and Test scope remain unchanged.
