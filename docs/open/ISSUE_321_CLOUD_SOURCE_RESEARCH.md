## 2. Discovery: factual taxonomy, usable media sources

**Genus identity authority:** [WMO cloud definitions](https://cloudatlas.wmo.int/definitions-of-clouds.html), [classification table](https://cloudatlas.wmo.int/tabular-guide-genus.html) and [identification guidance](https://cloudatlas.wmo.int/identifying-the-genus.html). These are not licenses for the WMO photographs. [WMO copyright](https://cloudatlas.wmo.int/en/copyright.html) restricts other copying/repackaging and may require permissions from the individual photographer/institution.

**Primary usable-photo discovery:** Wikimedia Commons is appropriate for item-level CC0/public-domain/CC BY/CC BY-SA vetting, but category inclusion is not expert confirmation and a Commons uploader is not necessarily the author. See [Commons reuse policy](https://commons.wikimedia.org/wiki/Commons:Reusing_content_outside_Wikimedia/en) and [license conditions](https://commons.wikimedia.org/wiki/Commons:Reusing_content_outside_Wikimedia/licenses/en). Scan category subcategories to acquire varied *manifestations*, not simply the first eight alphabetical files.

Search findings are **source-pool leads, not accepted exemplars**. Commons counts include illustrations, sunsets, repeat photographers, satellite images and misclassified mixed skies. Large counts do not demonstrate 8 qualifying images per genus.

**Supplemental:** NOAA [Ocean Service licensing guidance](https://oceanservice.noaa.gov/about/faq.html) and [OMAO image terms](https://www.omao.noaa.gov/image-licensing-usage-info) allow broad reuse of many federal stills but *not* automatically of third-party credited items. Check file-level owner, not agency domain. A meteorological agency's copyrighted teaching images are research references unless permission permits redistribution.

## 3. Per-photo acceptance and independent QA

**Priority order:** CC0/verified public domain → CC BY → CC BY-SA with correct derivative sharing. Reject no-license, noncommercial-only if redistribution cannot be justified under app scope, fair-use, unknown origin, misleading reuploads and any incompatible terms. For each file, store: stable asset ID, WMO genus ID, canonical Commons File URL or agency object URL, exact original URL and source upload ID, creator (not merely uploader), CC version and URL or public-domain legal basis, attribution and derivative license, original dimensions and SHA-256, metadata snapshot/retrieval date, photo event and source lineage, assigned exposure, crop/presentation notes, packaged dimensions/bytes/SHA-256, two independent reviewer IDs + dates, visible diagnostic, nearest competing genus and rejection reasoning.

**Intake workflow (repeat for every candidate):**

1. Open canonical file page, its file history, and original creator/rights declaration. Collect machine-readable imageinfo/ExtMetadata where useful, but human-check it; Commons metadata is not a rights guarantee. Record licenses/attribution at candidate time.
2. Review the *uncropped source* against WMO definition and nearest confusion set. Label ground/daytime/visible-light? Subject identifiable? Mixed genus? Enough sky context for angular element width, sun/halo or vertical extent? If uncertain, reject scored use; retain as “ambiguity example” only with an explicitly non-scored role.
3. Assign independent sourceLineageId (photographer or rights-origin identity) and photoEventId (same date/sky/geolocation/sequence where discoverable); group reuploads, edits, mirrors and burst frames. Compare exact original hashes and perceptual hashes plus manual visual contact sheets **across both Learn and holdout**. A transformed crop of the same exposure counts as *one*.
4. Two independent domain/media reviewers independently record accepted genus, visible cues and confusable alternative *before seeing each other's verdict*. Any conflicting genus or ambiguity flags → excluded from scored pool pending resolution/replacement. Keep rejection ledger.
5. Check actual 390px display and crop with full enough sky; inspect brightness, distortion, resolution, alternative text, watermarks/embedded labels and metadata leakage. Do not crop away halo, apparent scale context or anvil to match layout. Derivatives must retain same genus and photoEventId.
6. Freeze exposure assignment by asset ID before any student-visible release. Never use holdout in Reference, staging, formative, previews, testimonials, demo accounts or sampled UI screenshot fixtures. A visible leaked holdout is retired from Test, not silently reclassified after use.
7. Bake approved originals/derivatives locally for the offline-first PWA (no third-party runtime hotlinks). Check attributable credit/SA obligations, AVIF/WebP actual sizes, cold-start precache/retention and storage across #113. Rehash source and derivative bytes during production gate.
8. Run aggregate gate: per genus ≥8 accepted independent real photos, ≤3 globally exposed, ≥5 completely protected held-out; ≥2 lineages, ≥3 diverse manifestations, clear + less-ideal views, nonduplicate event groups, contrast coverage and ≥2 independent classification reviewers. Do not silently relax criteria for scarce genera.

The 80-image floor is **an Argus editorial choice**, not a WMO validation number or the Baeck et al. study's numeric recommendation. Perceptual-learning support for using varied exemplars: [Baeck et al., 2016](https://doi.org/10.3389/fpsyg.2016.01386) found better generalization with four versus one example in their object experiment. It does not prove that eight clouds suffice.

## 4. Versioned dataset and media controls (handoff; no UI/storage work here)

- Freeze a dataset version containing accepted asset IDs, content hashes, exposure split, scientific review receipts and manifest hash; make it reviewable without disclosing Test photos to the learner.
- A category ledger must not reveal which answer belongs to a heldout image via file basename, alt text, UI, screen reader names, requests or client logs. Publicly shipped static files can often be discovered by sophisticated learners; the product can prevent casual learning-path leakage, **not guarantee a secure exam**. Do not claim a psychometrically secure exam.
- Precache Test files where offline testing is supported, and ensure that caching does not render them in Reference. The actual storage/retention design is #113's remit, and manifest/domain integration is #296's.
- Track actual source and derivative byte totals and report worst-case budget and retry/eviction behavior before release. The inherited 180 KB guide is not an estimate for 80 independently varied photographs.
- Source candidates lacking second-review records are not score-ready even when used as historical guide heroes.
- If the 80-photo gate is not satisfied, publish only staged **unscored visual Learn** from legitimately available ≤3 photographed exemplars per genus; retain an explicitly labeled old **Cloud Vocabulary Test** and no new photographic mastery claim.
