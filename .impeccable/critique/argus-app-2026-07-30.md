## Design-specificity verdict

The visual language had recognizable Argus ingredients—dark olive surfaces, brass accent, eye mark—but the composition was category-interchangeable. A large marketing hero, four metric cards, repeated rounded topic cards, and eyebrow labels could have belonged to almost any generated dashboard.

## What worked

- The closed-scope product idea was expressed clearly.
- Track, status, and drill metadata were consistently modeled.
- Local-first data controls and authoring validation supported user trust.

## Priority issues and resolution

### P1 — The library opened as a landing page
The primary user need is to see what is due and begin. The oversized slogan displaced that task.

**Resolved:** replaced the hero with a compact, dynamic “Today’s practice” command surface.

### P1 — Repetitive card scaffolding obscured the content model
Stats, topics, modes, and panels all used similar rounded containers, flattening hierarchy.

**Resolved:** converted topics to a dense index, consolidated metrics into one status strip, and reduced nested surfaces.

### P1 — Desktop adaptation was cosmetic
The mobile bottom navigation merely floated at larger widths.

**Resolved:** introduced a fixed desktop side rail while retaining mobile bottom navigation.

### P1 — Product typography behaved like a brand surface
Georgia display type, fluid headings, and eyebrow labels added ceremony to routine actions.

**Resolved:** moved to one native UI sans family, fixed type sizes, and direct page headings.

### P2 — Interaction states and accessibility were incomplete
Keyboard focus, selected-state semantics, close-button labels, focus entry, and focus return needed hardening.

**Resolved:** added global focus-visible treatment, `aria-pressed`, `aria-current`, accessible close labels, modal focus entry/return, 44px targets, and reduced-motion handling.

## Remaining issues

- Replace native `confirm()` and `alert()` flows with accessible in-product confirmation and error surfaces.
- Add a first-run empty-state path for a genuinely blank imported library.
- Add automated accessibility and visual regression checks once browser automation is stable.
- Revisit the “Quick session” behavior: it currently chooses an available drill type rather than composing a truly mixed session.
